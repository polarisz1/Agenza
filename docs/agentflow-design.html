Technical Design · v0.2

AgentFlow 技术设计方案

在 Monorepo（pnpm workspace + Turborepo + uv）之上，构建单用户、本地桌面部署的 AI 工作流编排平台。桌面壳采用 Electron + PyInstaller，执行引擎采用自研轻量 DAG 调度。

MONOREPO / ELECTRON / SINGLE-USER
D1

设计目标与约束

01零外部依赖仅 Python + Node，SQLite 落盘，不需要消息队列、Redis 或容器。
02进程内执行引擎与 API 同进程，asyncio 调度，便于本地调试与取消。
03可观测节点级输入/输出/耗时持久化，SSE 实时推送执行事件。
04桌面原生体验Electron 壳提供托盘、原生窗口、自动更新；后端 PyInstaller 单文件。
约束落地方式
单用户不引入登录与权限；Electron 壳在本机进程内运行，FastAPI 仅监听 127.0.0.1。
桌面应用Electron 壳内嵌 PyInstaller 打包的 FastAPI 单文件 exe；壳主进程守护后端崩溃自动重启。
Monorepopnpm workspace（JS侧）+ uv workspace（Python侧），Turborepo 编排任务。
契约单一事实源后端 Pydantic schema 导出 OpenAPI YAML → openapi-typescript 生成前端类型。
SQLite开启 WAL + foreign_keys + busy_timeout；引擎侧写库串行化，避免 SQLite 单写者竞争。
前端约束React 18 + AntD 5 + Zustand + @xyflow/react；AntD ConfigProvider 覆写主色 #1F4E3D。

D5

执行引擎

5.1 运行生命周期

01Validate图结构、必填参数、变量可解析、provider 可用。
02Snapshot冻结 graph + inputs，写入 run（状态 running）。
03ScheduleKahn分层，每层 asyncio.gather + Semaphore(4)。
04Finalize汇总状态与token，写入 finished_at，推送 run.finished。

调度器不依赖"当前运行到第几步"的游标；每轮从 pending 集合中挑选"所有入边来源均已终态"的节点，天然支持并行分支与条件跳过。节点输出统一写入内存 outputs[node_id]，供变量解析读取。

5.4 重试、超时、取消

机制规则
重试attempt <= node.retry；仅对可重试错误（连接失败、超时、429、5xx）退避重试，间隔 1s × 2^attempt；参数校验错误与 4xx 不重试。
超时节点级 asyncio.wait_for(..., timeout=node.timeout_s or settings.DEFAULT_TIMEOUT)；超时视为可重试错误。
取消RunManager 持有 run_id -> asyncio.Task；取消时 task.cancel()，finally 中把未完成节点写为 canceled 并把运行置为 canceled。
跳过传播条件节点未激活的分支：其下游若"所有入边都来自跳过节点"则标记 skipped；失败节点的下游同样 skipped，不继续执行。
并发全局 Semaphore(ENGINE_MAX_CONCURRENCY=4)；默认同一工作流串行（已有 running 则拒绝新运行，返回 409）。

5.5 持久化与 SQLite 写竞争

  • SQLite 开启 PRAGMA journal_mode=WAL 与 busy_timeout=5000，读多写少场景足够。
  • 引擎写节点账本通过单一 asyncio.Lock 串行化，每次写入使用独立短 Session（asyncio.to_thread），不在 await 期间持有 Session。
  • SSE 事件与入库顺序：先入库再推事件，保证客户端收到事件后立即查询也能读到该节点记录。
  • 运行结束清理：按 RUN_RETENTION（默认 200/工作流）删除最旧 run 与其 node_run（级联删除）。

实时事件流（SSE）

GET /api/runs/{run_id}/events 返回 text/event-stream。前端用 EventSource 订阅；连接建立时先回放已落库的节点状态，之后推送增量。

       "duration_ms":842,"tokens_in":210,"tokens_out":388,"output_preview":"…"}

data: {"run_id":"r_8f2a","status":"success","duration_ms":4210,"total_tokens":1842}
事件载荷
run.startedrun_id, workflow_id, started_at
node.startedrun_id, node_id, attempt
node.logrun_id, node_id, level, message（模型流式片段或脚本输出）
node.finishedrun_id, node_id, status, duration_ms, tokens, error?, output_preview
run.finishedrun_id, status, duration_ms, total_tokens, failed_node_id?

前端断线时指数退避重连；重连携带 Last-Event-ID，后端从 node_run 中补齐缺失状态。不推送大对象：完整输入输出由详情接口按节点按需拉取，SSE 只带摘要。

桌面壳架构（Electron + PyInstaller）

// Electron main.js（~120行，核心逻辑）
const { app, BrowserWindow, Tray, Menu, ipcMain, dialog, shell, Notification } = require('electron');
const path = require('path');
const { spawn } = require('child_process');
const fs = require('fs');

let mainWin, tray, backendProc, backendPort;
const DEV = !app.isPackaged;

async function startBackend() {
  const port = DEV ? 8000 : findFreePort();
  if (DEV) { exec('python -m app.run', { cwd: '../apps/api' }); }
  else { backendProc = spawn(path.join(process.resourcesPath, 'backend.exe'), ['--port', port]); }
  await waitForBackend(port);  # poll /health endpoint
  backendPort = port;
}

function createWindow() {
  mainWin = new BrowserWindow({
    width: 1440, height: 900, autoHideMenuBar: true,
    webPreferences: { preload: path.join(__dirname, 'preload.js'),
                       contextIsolation: true, nodeIntegration: false, sandbox: true }
  });
  const url = DEV ? 'http://localhost:5173' : `http://127.0.0.1:${backendPort}/`;
  mainWin.loadURL(url);
  mainWin.on('close', (e) => { if (!app.isQuitting) { e.preventDefault(); mainWin.hide(); } });
}

app.whenReady().then(async () => {
  await startBackend();
  createWindow();
  setupTray();
  if (!DEV) setupAutoUpdater();  # electron-updater
});

app.on('before-quit', () => { app.isQuitting = true; backendProc?.kill('SIGTERM'); });

三层自动更新链路

层级更新方式是否重启应用
Electron壳electron-updater + GitHub Release / OSS；下载增量或全量安装包；Squirrel.Windows 完成替换✅ 壳退出 → Squirrel替换 → 拉起新壳（后端进程自动跟着重启）
FastAPI后端启动时 / 定时查版本API；下载新exe到temp/ → 写bootstrap.bat脚本 → 壳优雅退出后端进程 → bootstrap替换exe并重启壳✅ 壳重启，但前端dist未变则前端缓存可保留
前端distFastAPI定时查版本API → 下载dist.zip到temp/ → 原子替换frontend/dist/目录 → SSE通知前端软刷新 location.reload()❌ 最无感：前端软刷新，壳和后端都不重启
关键设计：三层更新独立、互不依赖。壳更新最重（NSIS安装包），前端更新最轻（软刷新）。所有更新前都校验SHA-512，失败则回滚到上一个版本。后端崩溃时主进程自动重启它，不影响壳窗口存活。

D11

安全与本地化

  • 监听范围：生产模式 FastAPI 默认只监听 127.0.0.1；Electron 壳内置后端的端口也绑定 localhost。
  • 密钥加密：Fernet（cryptography）加密后存入 provider.api_key_enc；主密钥生成于 Electron 壳首次启动时写入用户数据目录，可用 AGENTFLOW_SECRET_KEY 覆盖。
  • 密钥出站：API 响应只返回掩码尾号；日志过滤器拦截 sk-/Bearer 形态字符串；导出文件不含密钥。
  • 脚本节点：独立子进程（python -I -S），工作目录为临时目录，stdin/stdout 传 JSON，超时即 kill。
  • 路径校验：导入导出与数据目录操作统一走 Path.resolve() + 根目录白名单，拒绝目录穿越。
  • 单实例：Electron 壳启动时获取用户数据目录下的锁文件，避免两个后端共用同一 SQLite 文件。
  • Electron 安全基线：contextIsolation=true + nodeIntegration=false + sandbox=true；所有原生能力通过 preload contextBridge 白名单暴露。

风险与取舍

风险影响应对
SQLite 写竞争节点并发完成时写库抖动WAL + 单写锁 + 短 Session；如仍不足，后续可切 PostgreSQL（已有配置项）。
SSE 与进程重启运行中重启导致运行悬挂启动时扫描 running 状态运行，标记为 failed（"应用重启中断"）。
Provider 差异各家 JSON 输出与用量字段不一致Provider 适配层归一化 text / json / usage，不支持的能力降级为文本解析。
脚本安全本机代码执行风险子进程隔离 + 超时 + 明确提示；不做沙箱承诺，定位为可信本地功能。
画布性能大图拖拽掉帧仅选中节点重渲染；属性表单防抖；必要时限制同屏节点数并提示。
Electron 体积安装包 ~120MB这是 Chromium 的固有成本；Tauri 体积更小但需 Rust + WebView2 实测 AntD5 兼容性。
Electron Defender 误报首次安装被标记病毒EV证书签名 + Windows Hardware Dev Center 提交；Phase 1 先用自签名，后续升级。
