## 2. 事实基线

### 2.1 范围（冻结）

| 项 | 值 |
|---|---|
| 产品形态 | 单用户、本地桌面应用（Electron 壳 + FastAPI + React） |
| 核心价值 | **过程可见**：每一步的输入/输出/耗时/消耗可回看（v0.2 补全"输入"与"失败原因"） |
| 明确不做 | 多用户与权限、云端同步、在线模板市场、计费、移动端、i18n |
| 触发方式 | 手动运行 + 单节点调试；定时触发在 v0.2.1 |

### 2.2 技术栈（变更需 ADR）

pnpm + Turborepo / Vite 5 + React 18 + TS + Router v6 + Zustand + AntD 5 + @xyflow/react /
Python 3.12 + FastAPI + Pydantic v2 + SQLAlchemy 2.0 + SQLite(WAL) + Ruff /
自研 DAG（RunManager + Kahn + semaphore(4) + EventBus→SSE）/
FastAPI OpenAPI → contracts → TS 类型 / Electron + PyInstaller。

## 6. 执行规范（防幻觉）

1. **先确认再动代码**：开工前确认"本轮做哪个任务、改哪些文件、是否允许改"。
2. **先读再写**：改任何文件前先读到最新内容，不凭记忆。
3. **路径必查**：引用跨模块路径前先确认文件存在。
4. **禁令必守**：`AGENTS.md` 硬约束每次提交前对照（modules 平铺目录、contracts 手写 generated、前端手写 interface）。
5. **历史缺陷不复现**：`docs/code-review-*.md` 的缺陷清单当 checklist。
6. **TBD 不越界**：D 组"不做"的项撞到了先停下来问。
7. **验证后交付**：每个任务至少跑 `pnpm check`；涉及界面跑 `pnpm e2e`；不能靠"看起来应该行"。
8. **新增 feature 必过 AGENTS §7**（alembic revision + contracts:generate/check）。
9. **一个任务一个提交**，提交信息引用任务号与 backlog ID；跨里程碑不合并。

### 6.1 文档纪律

1. **状态只能由证据产生**：标 ✅ 必须写"哪条命令 / 哪次实跑"。
2. **一个事实只写一处**：技术栈/目录/安全基线引用 `AGENTS.md`，任务细节引用 `v0.2-plan.md`。
3. **里程碑收尾三件事**：更新本文件进度、更新验收文档、把验收命令固化进测试或 CI。
4. **文档与代码冲突时以代码为准**，当次提交修正文档。
