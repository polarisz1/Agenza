## 2. 用户与现状问题

### 2.1 目标用户（保持单用户、本地）

| 画像 | 场景 | 现在最大的痛点 |
|---|---|---|
| A · 独立开发者 / 数据工作者（主） | 每天把一段文本/一个网页/一批 JSON 加工成结构化结果；偶尔调 prompt | 跑失败不知道为什么；改参数要反复点；想回看"上次那版为什么好" |
| B · 效率工具爱好者（次） | 用 Python/HTTP 把本地小工具串起来 | 画布节点太少、信息太挤；想把常用流程存成模板复用 |
| C · 小团队内部分享（导出 JSON） | 把工作流发给同事导入 | 不知道对方缺哪个 provider；导入后节点变量对不上没有提示 |

### 2.2 三个真实任务走查（v0.1 实测）

1. **每天摘要一批反馈**：模板创建 → 填输入 → 运行 → 看输出。**卡点**：LLM 等待期间没有进度；失败时只有 `Run failed`；想比较两版 prompt 的差异只能人工抄。
2. **临时抓网页 → 抽取字段**：新建 → HTTP → 抽取 → 输出。**卡点**：HTTP 节点输出很长，运行详情只能看输出、看不到请求参数；抽取缺字段时的报错要展开才知道。
3. **把脚本包成小工具**：Python 节点 → 运行。**卡点**：开发态（`pnpm dev`，uvicorn reload）下 Python 节点**必然失败且错误为空**（见 §5-B1）；打包态正常，但开发者会被误导。

### 2.3 现有产品的"信任缺口"

- **看不到输入**：`node_run.input_json` 字段存在但从未写入、接口也不返回（`runs/service.py::_to_node_detail` 只映射 output）。"过程可见"目前只兑现了输出侧。
- **失败不可解释**：空的节点错误 + 通用 `Run failed`；没有错误分类、没有建议、没有"跳到出错节点"。
- **状态不可信**：列表里"草稿"的判定来自最后一次保存的校验结果，运行成功也不会变；用户无法手动"发布/就绪"。

### 2.4 状态语义现状（Q4 的证据）

- `WorkflowStatus = draft | ready`，`ready` 仅在 `PUT /api/workflows/{id}` 带 graph 且**无阻断问题**时自动写入。
- 通过模板创建的工作流初始为 `draft`；不打开编辑器保存一次，永远是"草稿"。
- 运行成功不会改变状态；运行失败也不会。
- 结论：这个字段当前表达的是"最后一次保存时的校验结论"，不是用户理解的"是否可用/是否发布"。**建议改造，不建议继续加语义**。

## 3. v0.2 目标、指标与非目标

### 3.1 产品目标（按优先级）

| # | 目标 | 用户可感知的结果 |
|---|---|---|
| G1 | **过程可见 2.0** | 每次运行能回答：每个节点吃了什么、吐了什么、为什么失败、和上次差在哪 |
| G2 | **编辑顺手** | 多选/复制/右键/搜索/快捷键，改一张图不再靠"一个一个点" |
| G3 | **模型体验可信** | 流式输出、模型列表可选、真实 provider 有验收结论 |
| G4 | **可复用** | 模板中心 + 版本历史，常用流程"存得下、找得到、回得去" |
| G5 | **第一次用就懂** | 首次启动 3 步引导 + 可运行示例，不用先读文档 |

### 3.2 成功标准（可测量，本地计算，不上报）

> 隐私优先：不做任何遥测。以下指标用**本地运行日志/数据库**计算，发布前手工抽样一次。

| 指标 | 现状（v0.1） | v0.2 目标 |
|---|---|---|
| 从"新建"到"第一次成功运行"的步骤数 | 8+（新建→拖 3 个节点→连线→填输入→运行） | **≤ 4**（模板/引导直达） |
| 失败运行中"能看到具体原因"的比例 | 有 error 的节点才显示；空错误时 0 | **100%**（错误兜底 + 分类 + 建议） |
| 运行详情可回看的字段 | 输出、耗时、token | 输出 + **输入** + 参数 + 模型 + 版本 |
| 常用编辑操作步数（复制节点 / 多选删除 / 定位节点） | 无 / 逐个删 / 肉眼找 | 1 步 / 1 步 / Ctrl+F |
| 100 节点拖拽帧率 | 62–64fps | **≥ 50fps**（不回归） |
| 质量门禁 | 168 / 42 / 5 | 只增不减，新增用例覆盖新功能 |

### 3.3 非目标（v0.2 明确不做）

多人协作与权限、云同步/分享链接、在线模板市场、计费与成本金额（D-7 维持）、i18n（D-9 维持）、移动端、自动更新与签名（backlog A）、人工确认、本地 RAG、子工作流（v0.3）。

## 4. 功能需求

> 优先级：**P0 = v0.2.0 必交付**；**P1 = v0.2.0 争取 / v0.2.1**；**P2 = v0.3**。
> 工作量：S ≤ 2 人日 / M 3–5 人日 / L 6–10 人日（单人开发估算）。

### F1 · 运行可观测性 2.0（P0，M，负责域：runs + engine + web/runs）

**用户故事**
- 作为调试者，我想在运行详情里看到每个节点**实际收到的输入**（变量解析后的值）和输出，这样我能判断问题出在数据还是配置。
- 作为使用者，我想在失败时一眼看到**为什么失败、去哪改**，而不是一句 `Run failed`。
- 作为反复调参的人，我想对比**两次运行**的节点状态/耗时/token/输出差异，判断改动是否有效。

**需求**
1. 节点输入落库与返回：
   - 执行前把 `run_inputs` + 直接上游输出（解析后的）写入 `node_run.input_json`（沿用现字段，不新增表）。
   - `NodeRunDetail.input` 在 API 返回中生效（契约字段已存在，补实现即可）。
   - 大输入沿用 1MB 截断策略（`limits.py`）。
2. 失败诊断：
   - 运行汇总错误取**首个失败节点的具体错误**；无错误文本时兜底为 `异常类型 + 节点名`（不再出现空字符串/`Run failed`）。
   - 节点错误分类（前端映射，不新增契约字段）：鉴权 / 网络 / 超时 / 脚本退出 / 变量解析 / JSON 解析 / 工具异常；每类给 1 句建议 + 1 个动作（如"去模型配置"、"打开节点"）。
   - 运行详情：失败节点自动展开、置顶；提供"跳转到编辑器并选中该节点"。
3. 运行对比：
   - 入口：运行列表勾选两次运行 → "对比"；运行详情内"与上一次对比"。
   - 视图：节点表格（状态/耗时/token/模型/错误）+ 输出文本并排 diff（行级，简单算法，不引新依赖）；只对比两次都存在的节点 id，缺失节点标注"只在 A/B"。
   - 契约：`GET /api/runs/compare?ids=a,b`（返回两次 RunDetail + 节点对齐结果）或前端复用两个 `GET /api/runs/{id}`；**推荐后端出对齐结果**，前端不做业务对齐。
4. 运行详情增强：时间线/表格切换、按状态筛选、复制输出、导出单次运行 JSON、显示"本次运行使用的图版本"（依赖 F5）。

**验收**
- 后端用例：Python 节点输入/上游被写入 `input_json`；空异常时 run.error 非空且含节点名。
- API 用例：`GET /api/runs/{id}` 的 `nodes[].input` 非空；`/api/runs/compare` 返回对齐结果。
- E2E：跑一次 Python 模板 → 打开运行详情 → 能看到"输入"区块与"输出"；制造一次脚本失败 → 错误分类文案可见、可跳转节点。
- 性能：输入/输出各 1MB 时详情接口 < 500ms（本地）。

### F2 · 编辑效率包（P0，M，负责域：web/workflows）

**用户故事**
- 作为编排者，我想框选多个节点一起移动/删除/复制，不想一个个点。
- 作为编排者，我想右键节点/画布/连线做操作，不想去右边找按钮。
- 作为编排者，我想 Ctrl+F 定位节点，不想在大图里用肉眼找。

**需求**
1. 多选与批量：Shift+点击、框选（React Flow 自带）、全选 Ctrl+A；批量移动、删除、启用/禁用、复制。
2. 复制/粘贴/副本：Ctrl+C / Ctrl+V（偏移 24px 粘贴）、Ctrl+D（副本）；跨工作流粘贴（剪贴板存内存 + 序列化，不落 OS 剪贴板，避免格式问题）。
3. 右键菜单：
   - 节点：调试此节点 / 复制 / 禁用 / 删除 / 查看最近输出。
   - 画布：粘贴 / 全选 / 自动布局 / 适应视图。
   - 连线：删除 / 反转方向（可选）。
4. 画布搜索：Ctrl+F 打开节点搜索浮层（按名称/类型），回车定位并高亮。
5. 节点专属渲染（UI 设计文档出具体形态）：
   - input：字段名 + 类型 + 必填；
   - llm：模型 + prompt 首行 + 温度；
   - extract：字段数 + 前 3 个字段名；
   - http：METHOD + host + 超时；
   - python：行数 + 超时 + 上次耗时；
   - condition：左值/运算符/右值；
   - merge：策略 + 入边数；
   - output：字段 + 来源。
   - 运行态：状态徽标 + 耗时（运行中实时计时）+ 失败原因截断。
6. 连线体验：拖拽时高亮可连端口、不可连端口置灰；非法放置给出一次 toast（含原因）；边可选中、可删除；条件边保留"真/假"标签。
7. 快捷键表（与 UI 文档一致）：Ctrl+S 保存、Ctrl+Z/Shift+Z、Ctrl+C/V/D/A、Delete、Ctrl+F、Ctrl+K（命令面板，P1）、Esc 取消选择。

**验收**
- 单测（store）：多选删除、复制粘贴的 id 重映射、批量禁用；粘贴后节点名唯一。
- E2E：框选 2 节点 → 删除 → 撤销恢复；Ctrl+C/V 复制节点；右键菜单"复制"；Ctrl+F 定位。
- 不回归：100 节点拖拽 ≥ 50fps；撤销栈语义不变（一次操作一个撤销点）。

### F3 · 模型体验（P0，M，负责域：providers + engine + web/models、workflows）

**用户故事**
- 作为使用者，我想看到模型一个字一个字出来，而不是等 20 秒后突然出现。
- 作为使用者，我想在节点里直接从"服务商可用模型"里选，而不是手打模型名。
- 作为维护者，我想知道三家适配器在今天真的能用。

**需求**
1. 流式输出：
   - Provider 适配层新增 `stream()` 契约（OpenAI `stream:true`、Ollama `stream:true`、Anthropic SSE）；`chat()` 保留用于测连与非流式场景。
   - 引擎新增 SSE 事件 `node.delta`（`{node_id, seq, text}`，不落库）；`run.finished` 仍是权威结果。
   - 前端：运行抽屉实时追加 token；节点卡片显示"生成中"光标；属性面板"输出"Tab 实时预览。
   - 失败/取消时保证流正确关闭（不泄漏连接）。
2. 模型列表：
   - `GET /api/providers/{id}/models`：OpenAI 兼容 `/models`、Ollama `/api/tags`；Anthropic 无公开列表 → 返回内置静态候选（标注"手动输入也可"）。
   - 节点属性面板模型字段改为 `Select`（可输入搜索 + 手动输入兜底），带刷新按钮。
   - 缓存 5 分钟；失败不影响手动输入。
3. 真实 provider 验收矩阵（发布前人工 + 可重复脚本）：
   - 四类目标：OpenAI 兼容（含 DeepSeek）、Ollama、Anthropic 兼容。
   - 每家至少：普通对话、JSON 模式、流式、鉴权失败、超时 5 个用例；结果记录到 `docs/v0.2-provider-matrix.md`。
4. 用量展示：运行详情与工作流列表聚合 token（输入/输出/总计）；不做金额（D-7）。

**验收**
- 单测：三个适配器 stream 的请求体/事件解析（httpx.MockTransport）；流中断时连接关闭。
- 后端：SSE 出现 `node.delta` 且 seq 单调；`run.finished` 的 output 与流式拼接一致。
- E2E：用假 provider（本地 echo SSE）跑 LLM 模板，断言"完成前已出现增量文本"。
- 发布门槛：矩阵中 4 家 × 5 用例全部有结论（通过/环境缺失需注明）。

### F4 · 模板中心 + 首次引导（P0，S–M，负责域：web/workflows、settings）

**用户故事**
- 作为新用户，我第一次打开就能跑通一个例子，而不是先研究"服务商"是什么。
- 作为常用者，我想从模板库挑一个接近的流程改，而不是从空白开始。

**需求**
1. 模板中心：
   - 入口：工作流列表"新建 → 模板中心"；空态主按钮。
   - 模板卡片：名称、一句话、所需能力标签（Python / HTTP / LLM / 条件 / 无需模型）、节点数、预览缩略图（静态图或简版画布快照）。
   - 首批 8 个：文本摘要、网页抓取摘要、结构化抽取、文本分类分流、批量 JSON 清洗（Python）、HTTP 聚合、条件重试示例、脚本入门。
   - "无需模型"的模板必须能零配置跑通（Python/HTTP/条件）。
2. 首次引导（仅当检测到无服务商且无工作流时触发，可跳过）：
   - 第 1 步：选服务商类型（OpenAI 兼容 / Ollama / Anthropic）→ 填地址/Key → 测连。
   - 第 2 步：选一个模板（默认"文本摘要"）。
   - 第 3 步：填输入 → 运行 → 看到第一次成功输出。
   - 完成后不再自动弹出；设置页可"重新观看引导"。
3. 空态体系：工作流列表 / 画布 / 运行记录 / 模型配置 / 设置，各自给"下一步做什么"（UI 文档出文案与布局）。

**验收**
- E2E：清空 provider 与工作流 → 首次启动出现引导 → 走完 3 步 → 运行成功；再次进入不弹。
- 模板：8 个模板全部能通过 `validate` 且"无需模型"的 4 个能直接跑成功（CI 里用假 provider 跑 LLM 模板）。

### F5 · 版本历史（P1，M，负责域：workflows + web/workflows）

**用户故事**
- 作为反复调参的人，我想回到"上周那版"，也想知道某次运行为什么是那个结果。

**需求**
1. 自动快照：工作流保存时，若图内容（nodes/edges/inputs）与上一版不同，写一条版本记录（保留最近 50 版/工作流；超过按时间清理）。
2. 版本列表：时间、节点数、变更摘要（增删节点/连线数量）、"本次运行"标记；可预览（只读画布）、可恢复。
3. 恢复语义：恢复 = 把该版本内容写回当前图并**生成一个新版本**（不删除历史）；恢复前提示"当前未保存修改将保留为新版本"。
4. 运行关联：`run` 增加 `version_id`（可空，迁移 0003）；运行详情显示"使用的版本"并可跳转预览。
5. 契约：`GET /api/workflows/{id}/versions`、`GET .../versions/{vid}`、`POST .../versions/{vid}/restore`；`WorkflowVersion` schema 进 OpenAPI。

**验收**
- 迁移：`alembic upgrade head` 新增表与字段，老库无损。
- 后端用例：保存两次不同图 → 两个版本；恢复 → 新版本且当前图等于目标版本；清理策略生效。
- E2E：改图 → 保存 → 看版本 → 恢复 → 画布内容回退。

### F6 · 定时触发（P1 → 建议 v0.2.1，M，负责域：runs + settings + web）

**需求（最小版）**
- 每个工作流可配置 0/1 个计划：每天 HH:mm、每周几 HH:mm、每 N 分钟（N ≥ 5）。
- 触发来源 `scheduled` 写入 run.trigger；并发策略沿用"同工作流串行"（已有 running 则跳过并记一条 `skipped` 运行，便于解释）。
- 计划开关 + 下次运行时间展示；应用未运行时错过不补跑（明确写出）。
- 不做：cron 表达式编辑器、错过补跑、失败通知、时区（本机时区）。

**验收**：假时钟单测（下三次触发时间）；E2E 用"每 5 分钟"不现实 → 用可注入时钟的后端用例覆盖；UI 只验证配置与展示。

### F7 · 暗色主题（P1 → v0.2.1，S–M，负责域：web/shared + 画布）

- 跟随系统（`prefers-color-scheme`）+ 手动三态（跟随/浅色/深色），设置存本地。
- 画布：背景、点阵、边、节点、MiniMap 全量适配；节点类型色在暗色下提亮 10–15%。
- 验收：对比度检查（正文 ≥ 4.5:1）、截图评审、E2E 断言 body 主题属性切换。

### F8 · 设置与数据管理增强（P1 → v0.2.1，S）

- 桌面能力接入：打开数据目录、打开日志、查看日志尾部（只读）。
- 自动备份：每日首次启动导出一次备份到 `data/backups/`，保留 7 份；设置页可关闭。
- 数据占用展示（库大小、运行条数、节点记录数）。
- 明确 `language` 项：v0.2 移除该设置（D-9 不做 i18n），避免"改了没效果"。

### F9 · 单工作流导入/导出（P1 → v0.2.1，S）

- 工作流详情/列表行提供"导出此工作流"（含版本？不含）；导入支持单文件、多文件、全量备份。
- 导入预览显示：节点数、缺失 provider（按 provider_id 比对）、变量引用无法解析的节点（复用校验器）。

### F10 · 子工作流（P2，L，v0.3）

- 新节点类型 `workflow`：选择已发布工作流 + 输入映射；执行时内联（不新建 run），递归深度上限 3，环检测。
- 需要先有"发布/版本"概念（F5 是其前置），故放 v0.3。

## 5. 随 v0.2 一并修复的 v0.1 缺陷（必须）

| ID | 问题 | 证据 | 处置 | 工作量 |
|---|---|---|---|---|
| B1 | **开发态（uvicorn reload）Python 节点 100% 失败，且错误为空** | 根因：uvicorn 0.54 在 Windows 且 `use_subprocess=True`（reload/多 worker）时用 `SelectorEventLoop`，不支持 `asyncio.create_subprocess_exec` → `NotImplementedError`（空消息）；`app.run` 在 DEBUG 默认 true 时启用 reload | **✅ v0.1.1 已修**：执行器在无 subprocess 支持的 loop 上降级为"线程 + Popen"（保留超时/取消 kill）；新增 4 条降级用例，`DEBUG=true` 实跑验证通过 | 已交付 |
| B2 | 运行错误丢失具体原因 | 空异常 → `str(exc)==""` → `_summarize` 落到 `Run failed`；详情红框只显示它 | **✅ v0.1.1 已修**：`describe_exception` 兜底为"类型（无错误信息）"；`_summarize` 改为"N 个节点失败（未提供错误信息）"；新增 5 条用例 | 已交付 |
| B3 | 节点输入从未落库/返回 | `node_run.input_json` 存在；`_make_node_started` 不写、`_to_node_detail` 不映射 | 并入 F1 | S |
| B4 | 工作流状态语义不可控 | `ready` 只是"最后一次保存校验通过"；API 创建的图恒为 draft | 按 Q4 改造为"可用性 + 最近运行"，删除手动状态展示 | S |
| B5 | 列表页操作列在 1440 宽被裁切 | 7 列总宽超容器，`Table` 未设 `scroll.x`、操作列未固定 | `scroll={{x:1100}}` + `fixed:'right'`；列宽重排（UI 文档） | S |
| B6 | 属性面板开关被拉伸成整行 | `.afe-field` 为 flex column，AntD Switch 被 `align-items: stretch` 拉满 | `.afe-field > .ant-switch { align-self: flex-start }` 或统一 Field 布局 | S |
| B7 | 页面标题重复（AppLayout 顶栏 + 页面 H1） | 工作流/运行/模型/设置四页均双层标题 | 顶栏改为面包屑/上下文标题，页面内 H1 仅保留一处（UI 文档 §2） | S |
| B8 | 空态/错误态覆盖不全 | 模型页已补；运行详情失败信息弱、画布空态只有一行 | 统一空态组件与文案（UI 文档 §5.9） | S |

## 6. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 100 节点拖拽 ≥ 50fps（v0.1 基线 62–64）；运行详情首屏 < 1s（本地）；流式首 token 额外延迟 < 300ms（相对非流式） |
| 可靠性 | 流式连接中断自动回退到最终结果；版本恢复为事务；定时触发跳过时写明原因；任何异常不得出现空错误 |
| 数据 | 版本/运行/节点记录均按保留策略清理；备份文件不包含密钥；截断策略沿用 1MB/2MB |

| 可访问性 | 键盘可完成核心流程（编辑→运行→查看）；正文对比度 ≥ 4.5:1；焦点可见；支持 `prefers-reduced-motion` |
| 兼容 | Windows 10/11 x64；窗口最小 1100×700；无移动端 |
| 国际化 | 保持简体中文（D-9） |
