## 1. 验收项（每家 5 条）

| # | 用例 | 通过标准 |
|---|---|---|
| 1 | 普通对话（非流式） | 返回文本；`model`/token 正确；节点成功 |
| 2 | JSON 模式 | LLM `format=json` 或抽取节点返回对象；失败有可读错误 |
| 3 | 流式 | 运行抽屉在结束前出现增量文本；最终输出与增量拼接一致 |
| 4 | 鉴权失败 | 401/403 → "鉴权失败（HTTP 401/403）" + 去模型配置 |
| 5 | 超时 / 连接失败 | 超时 → "执行超时"；地址不可达 → "无法连接到模型服务地址" |

## 5. 本次联调发现并修复

1. **DeepSeek 模型名变更**：`GET /v1/models` 已无 `deepseek-chat`，现为 `deepseek-flash` /
   `deepseek-v4-pro`。首启引导默认模型与模型配置占位符已改为 `deepseek-flash`。
2. **Anthropic 兼容端点的 `tool_choice` 限制**：DeepSeek 的 thinking 模式返回 400
   `Thinking mode does not support this tool_choice`。`AnthropicCompatProvider.chat`
   在 JSON 模式下检测到该错误后，自动去掉 `tools/tool_choice`，改用
   "system 要求只输出 JSON + 解析文本"，并新增单测锁定该降级路径。

## 6. 有环境时如何补跑

1. 在「模型配置」添加服务商，点「测试」应返回 `Connection OK`。
2. 运行内置模板「文本摘要（LLM）」：确认结束前有流式文本，结束后输出完整。
3. 运行模板「结构化抽取」：输出应是 JSON 对象（不是字符串）。
4. 把 Key 改错：应出现 `鉴权失败（HTTP 401/403）`。
5. 把地址改成 `http://127.0.0.1:9/v1`：应出现 `无法连接到模型服务地址`。
6. 每条结果回填 §3，作为发布证据。
