### 1.1 工作流编辑器：从"单人画板"到"团队画板"

#### 问题
当前编辑器是单用户设计：没有协作感知、没有编辑锁定、没有"谁在改什么"的可见性。

#### 调整设计

**A. 画布顶部增加协作状态条**

```
┌─────────────────────────────────────────────────────────────────────────┐
│ 🔒 锁定：由 @alice 编辑中（2 分钟前）                        [申请解锁] │
│ 👥 在线：@alice  @bob  @carol（viewer）                                  │
├─────────────────────────────────────────────────────────────────────────┤
│ [保存] [运行 ▼] [版本 ▼] [模板] [导出]  ← 工具栏保持不变                │
└─────────────────────────────────────────────────────────────────────────┘
```

**设计要点**：
- **乐观锁 + 协作状态**：打开工作流时自动"锁定"（Owner 可强制解锁）；锁定者 15 分钟无操作自动释放
- **在线光标**：其他在线成员在画布上的位置用带用户名的小光标显示（类似 Figma）
- **变更指示**：被别人修改的节点会有 2 秒的黄色闪烁提醒
- **版本对比入口**：顶部"版本"下拉增加"与他人的未保存修改对比"

**B. 节点属性面板：从"参数编辑器"升级为"AI Prompt Studio"**

当前属性面板只做参数编辑，SaaS 场景下需要增强 prompt 工程体验：

```

│ 🤖 LLM 调用 · 竞品分析 Prompt                        │
├─────────────────────────────────────────────────────┤
│ 模型: [deepseek-v3      ▼]     温度: [0.7]          │
│                                                      │
│ System Prompt ───────────────────────────────────── │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 你是一个专业的竞品分析师...                        │ │
│ │                                                  │ │
│ │ 💡 Prompt Library  |  📊 最近效果: 成功率 87%    │ │
│ └─────────────────────────────────────────────────┘ │
│                                                      │
│ User Prompt ─────────────────────────────────────── │
│ ┌─────────────────────────────────────────────────┐ │
│ │ 请分析以下竞品信息:                               │ │
│ │ {{http_fetch_1.output.body}}                     │ │
│ │                                                  │ │
│ │ 🧪 变量预览 |  📐 Token 估算 |  ▶️ 测试运行       │ │
│ └─────────────────────────────────────────────────┘ │
│                                                      │
│ Output Format: [JSON Schema ▼]                       │
│ ┌─────────────────────────────────────────────────┐ │
│ │ {"competitor": string, "strengths": string[],   │ │
│ │  "weaknesses": string[], "summary": string}     │ │
│ │ ✅ JSON Schema 校验通过 | 不通过时自动修正       │ │
│ └─────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────┘

**新增能力**：
- **Prompt Library**：保存团队常用的 prompt 模板（如"专业摘要""结构化抽取""多轮问答"）
- **最近效果统计**：该 prompt 在最近 10 次运行的成功率、平均耗时、Token 消耗
- **变量预览**：点击变量 `{{xxx.yyy}}` 可以预览它在上一次运行中的实际值
- **Token 估算器**：输入内容的同时实时估算会消耗多少 Token（按当前模型单价显示预估费用）
- **JSON Schema 校验 + 自动修正**：输出 JSON 不符合 schema 时，自动在输出节点给出"建议修正字段"

### 2.2 AI Gateway（E5）—— 成本控制与模型路由

#### 核心价值
AgentFlow 的 AI Gateway 做三件事：
1. **模型路由**：根据任务类型自动选"最便宜/最快/质量最高"的模型
2. **成本控制**：Token 预算告警 + 硬上限停机
3. **性能监控**：实时追踪每个模型的延迟/成功率/Token 效率

#### 引擎侧改造

```python
# AgentFlow 引擎中新增 ModelRouter（在 Provider 层之上）

class ModelRouter:
    def select_model(self, task_type: str, output_schema: dict | None) -> ProviderModel:
        """根据任务类型和输出要求选模型"""
        
        # 1. 检查预算是否够
        if self._budget_exhausted():
            raise BudgetExhaustedError("月度预算已用完，请联系管理员")
        
        # 2. 查路由表
        route = self._routing_policy.lookup(task_type, output_schema)
        
        # 3. 首选模型不可用时自动降备选
        for model in route.candidates:
            if self._model_available(model):
                return model
        
        raise NoAvailableModelError("所有候选模型当前都不可用")

    def track_usage(self, model: str, input_tokens: int, output_tokens: int, cost: float):
        """记录本次调用消耗"""
        self._budget_tracker.add(cost)
        self._alert_manager.check_and_fire(self._budget_tracker.current, self._budget_tracker.limit)
```

### 2.4 计量与计费（E4）

#### 计量模型设计

| 计量指标 | 说明 | 数据来源 |
|----------|------|----------|
| **工作流数量** | 工作空间内"已发布"状态的工作流数 | `workflow.published=true` |
| **月度运行次数** | 所有触发方式的运行总数 | `run.created_at` + `run.status != cancelled` |
| **Token 消耗量** | 所有 LLM / EXTRACT 节点的 input + output token 总量 | `node_run.input_tokens` + `output_tokens` |
| **存储用量** | 运行记录 + 导出文件 + 版本历史的总大小 | PostgreSQL 表大小 + S3 对象大小 |

## Part 4 · 不做清单（Hard Out of Scope for SaaS v1）

为保持聚焦，以下功能明确排除在 SaaS v1 之外：

| # | 功能 | 理由 | 计划时机 |
|---|------|------|----------|
| 1 | 移动端（iOS/Android） | SaaS 核心在 Web，移动端会大幅分散精力 | v2+ |
| 2 | i18n（多语言界面） | 当前用户集中在中国市场；英文 v1.5 考虑 | v1.5+ |
| 3 | 实时 Figma 式协作光标 | 技术复杂度高（WebSocket CRDT），且 v1 场景下"锁定+通知"够用 | v1.2+ |
| 4 | Marketplace（用户发布模板） | 需要审核系统 + 分成机制 + 内容安全 | v2+ |
| 5 | ML 自动调参（自动选 prompt / 自动优化模型） | 有趣但非核心；先靠 AI Gateway 的简单规则 | v1.3+ |
| 6 | 工作流 DSL（YAML / Python 定义） | 视觉编辑器是核心价值；DSL 可作为 API 层补充 | v1.4+ |
