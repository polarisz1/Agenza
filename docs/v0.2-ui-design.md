# AgentFlow v0.2 UI / UX 设计说明（待审核）

> **作者**：资深 UI 设计专家（受委托，基于 2026-11-01 的 v0.1 实际渲染截图与现有视觉规范）
> **配套**：`docs/v0.2-prd.md`（产品范围）、`docs/ui-design/index.html`（v0.1 视觉规范，继续沿用纸张感与墨绿主色）
> **版本**：v0.2.0-draft · 2026-11-01
> **状态**：等你审核；本轮只出文档与线框图，不写样式代码
> **一句话**：v0.1 的骨架和气质是对的；v0.2 要解决"信息挤、层级平、状态弱、操作重"四个问题。

## 0. 设计结论（先看这 6 条）

1. **保留**：纸张底色 + 墨绿主色 + 三栏画布 + 节点类型色。这是产品的辨识度，不换。
2. **重做信息层级**：全站统一"顶栏 = 面包屑 + 全局动作，页内 = 标题 + 主操作"；去掉现在的双层标题。
3. **重做节点卡**：8 类节点不再长一个样；节点是画布上的"信息卡"，不是标签。100% 缩放下必须可读。
4. **重做运行观测**：运行详情从"日志列表"升级为"可诊断的工作台"（输入/输出/错误/对比/版本）。
5. **减轻操作重量**：高频操作从"右侧面板找"变成"画布上直接做"（右键、多选、快捷键、命令面板）。
6. **统一状态语言**：所有状态用同一套颜色 + 文案 + 图标，绝不出现"草稿/就绪"这种用户无法控制的状态。

**需要你选一个视觉方向（Q1）**：

| 方向 | 描述 | 适合 | 我的建议 |
|---|---|---|---|
| **A · 精炼工作台**（推荐） | 降低装饰，信息密度适中；画布留白更多；节点卡更大更清楚；只在需要时展开细节 | 长时间使用、专业用户 | ✅ 选 A，v0.2 按此落地 |
| B · 信息仪表盘 | 首屏塞入更多统计（运行成功率、token 趋势、最近活动） | 想把 AgentFlow 当"工作台首页" | 会把 v0.2 拖成 4 周以上；建议 v0.3 |

## 2. 设计原则（v0.2 版）

1. **过程可见优先**：任何页面先回答"发生了什么、为什么"。统计和装饰让位。
2. **画布是主角**：编辑器里除节点/连线/运行反馈外的一切都可收起；空闲时画布 ≥ 70% 面积。
3. **一屏一事**：一个页面只有一个主行动（主按钮），其余为次/文字按钮；危险操作永远需要确认。
4. **状态永远可读**：颜色 + 图标 + 文案三重编码，不依赖颜色单一通道（色弱可用）。
5. **键盘可达**：核心旅程（编辑→运行→查看结果）不依赖鼠标；快捷键有唯一入口（命令面板）。
6. **克制动效**：只用于"状态变化/空间关系"，150–200ms ease-out，尊重 `prefers-reduced-motion`。

## 5. 组件规范

### 5.1 按钮

| 类型 | 使用场景 | 规格 |
|---|---|---|
| Primary | 每屏唯一主行动（新建/运行/保存并运行） | 高 32，圆角 6，brand-700 |
| Default | 次要操作（校验/自动布局） | 高 32，边框 line |
| Text | 面板内低频操作（收起/清空/重试） | 高 28，无边框 |
| Danger | 删除（配合 Popconfirm） | 文字红或红底白字只用于最终确认 |
| Icon | 工具栏（撤销/重做/缩放） | 28×28，hover 底色 brand-50，带 tooltip + 快捷键 |

文案规则：动词开头、≤ 6 字；"保存并运行"这种复合动作要拆开或明确顺序。禁用态必须给 tooltip 说明原因。

### 5.2 表格（工作流 / 运行记录）

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 工作流                                             [状态▾] [排序▾] [搜索…] [+新建] │
├──────────────┬──────────────┬──────────────┬────────┬──────────────┬─────────┤
│ 名称          │ 可用性        │ 最近运行      │ 节点数  │ 最近编辑      │ 操作(固) │
├──────────────┼──────────────┼──────────────┼────────┼──────────────┼─────────┤
│ ● 文本处理示例 │ ✓ 可用        │ ✓ 成功 2 分钟前│ 3      │ 19:45        │ ⋯       │
│   输入→脚本→输出│ 0 个阻断      │ 0.9s · 128 tok│        │              │         │
│ ● 错误分支示例 │ ⚠ 2 个提示    │ ✕ 失败 5 分钟前│ 5      │ 19:40        │ ⋯       │
│   条件分流演示  │ 0 个阻断      │ Run failed→   │        │              │         │
└──────────────┴──────────────┴──────────────┴────────┴──────────────┴─────────┘
```

- **列宽**：名称 280（自适应）/ 可用性 140 / 最近运行 200 / 节点数 80 / 最近编辑 140 / 操作 120（固定右）。
- 名称列两行：主名（13/600）+ 描述（12/ink-500，单行省略，tooltip 全文）。
- 可用性列：`✓ 可用` / `⚠ N 个提示` / `✕ N 个阻断` / `未校验`（点击触发校验）。
- 最近运行列：状态图标 + 状态中文 + 相对时间 + 耗时/token（次级行）。
- 操作列：`编辑` 图标按钮 + `⋯` 更多（复制/导出/删除）；删除在菜单里且二次确认。
- `scroll={{ x: 1100 }}`，操作列 `fixed: 'right'`；空数据用 §5.9 空态（不是"暂无数据"）。
- 行 hover 底色 `--brand-50` 50%；选中行（用于对比）左侧 2px brand 条 + 复选框常显。

### 5.3 节点卡 v2（核心）

尺寸：**宽 208px，最小高 64px**；内边距 10/12；圆角 10；边框 1px `--line`；阴影 1。

```
┌───────────────────────────────┐
│ ▎🤖  LLM1                 ✓ 成功 │  ← 类型条 + 图标 + 名称 + 状态徽标
│   deepseek-chat · T=0.3        │  ← 主摘要（12px）
│   请用 3 句话摘要以下内容…       │  ← 次摘要（12px，1 行省略）
│   1.2s · 128 tok          ⋯    │  ← 运行元信息 / hover 出现菜单
└───────────────────────────────┘
   ● 输入端口                       ● 输出端口
```

**通用结构**
1. 头部：3px 类型色条 + 类型图标（14px）+ 名称（13/600，省略）+ 状态徽标（11px）。
2. 主体：主摘要行（类型专属，见下表）+ 次摘要行（可选，1 行省略）。
3. 底部（运行后出现）：耗时 · token/模型/行数（按类型）+ hover 出 `⋯` 菜单。
4. 端口：左侧输入（9px→命中区 16px），右侧输出；条件节点右侧两个端口带"真/假"内联标签。
5. 状态：
   - 运行中：边框 info 色 + 顶部 2px 进度条（不确定进度）+ 计时；
   - 成功：状态徽标绿；失败：**左侧 3px danger 竖条** + 徽标红 + 底部红色错误首行；
   - 跳过：虚线边框 + 遮罩 40% + "已跳过"徽标（tooltip 原因）；
   - 校验问题：右上角 warning 小圆点（不是整卡红框，避免和运行失败混淆）。
6. 选中：2px brand 环 + 阴影 2；多选：加 `✓` 角标。
7. 缩放：节点内部字号不随缩放补偿（保持可读）；`fitView` 最大 0.9；< 0.6 缩放时隐藏次摘要，只留标题+状态（性能与可读性）。

**8 类专属摘要**

| 类型 | 主摘要 | 次摘要 |
|---|---|---|
| input | `字段 key · 类型` | 必填/默认值 |
| llm | `模型名 · T=温度` | system/prompt 首行 |
| extract | `N 个目标字段` | 前 3 个字段名 |
| http | `METHOD host/path` | 超时 / 上次状态码 |
| python | `脚本 N 行 · 超时` | 上次耗时 / 退出码 |
| condition | `左值  op  右值` | 真/假分支数 |
| merge | `全部到达 / 任一到达` | 入边 N 条 · 字段名 |
| output | `字段名 ← 来源` | 格式（text/json/markdown） |

### 5.4 画布与连线

- 布局：左侧节点库 220（可收起 48）；右侧属性面板 320（可收起）；底部运行面板空闲 40 / 展开 240（可拖拽高度，范围 160–480）。
- 节点库：分组标题 sticky，组内项高 48（图标 + 名称 + 一句描述），搜索框固定顶部；**独立滚动**，不被运行面板裁切。
- 底部状态栏：`3 个节点 · 2 条连线 · 100%`（左）+ 缩放控件（右），替代现在叠在画布上的组合。
- 背景：点阵 16px；暗色下点阵对比度 ≤ 8%。
- 连线：
  - 默认 1.5px `#B9C2B8`；hover 2px brand-500；选中 2px brand-700 + 端点圆点；
  - 条件边：真=brand-500 实线 + "真"标签；假=`#9AA39A` 虚线 + "假"标签；
  - 运行中：沿边流动虚线（200ms 一步，reduced-motion 关闭）；
  - 非法连接：拖拽时目标端口置灰 + 一次 toast（原因文案来自 `connectionIssue`）。
- MiniMap：160×110，节点按类型色填充、当前视口白框；点击跳转。
- 快捷键提示：`?` 打开快捷键表（全局）。

```

- 顶部：返回、run 短 id、状态徽标、主操作（重跑）、次操作（对比/导出）。

```

│ 输入1                       │ ✓ 0ms                │ ✓ 0ms                  │

### 5.9 空态、加载、错误（统一组件 `EmptyState`）

结构：图标（48，线框风格）+ 标题（14/600）+ 一句说明（13/ink-500）+ 主按钮 + 次提示（12）。

| 页面 | 标题 | 说明 | 主按钮 |
|---|---|---|---|
| 工作流列表 | 还没有工作流 | 从模板开始，或创建一张空白画布 | 从模板开始 / 空白新建 |
| 画布 | 从左侧拖入一个节点 | 建议顺序：输入 → 处理 → 输出 | 插入示例流程 |
| 运行记录 | 还没有运行记录 | 打开一个工作流点"运行" | 去工作流 |
| 运行详情（无节点） | 这次运行没有产生节点记录 | 可能启动即失败；查看错误详情 | 查看错误 |
| 模型配置 | 还没有配置模型服务商 | 支持 OpenAI 兼容 / Ollama / Anthropic | 添加服务商 |
| 设置-备份 | 还没有备份 | 开启自动备份后会每天生成一份 | 立即备份 |

- 错误：Alert 内联 + 重试按钮 + 错误码/时间（可复制），不只 toast。
- 全局：后端不可达时顶栏下方常驻条"后端未连接 · 重试"，所有写操作禁用并解释。

## 6. 关键流程（交互序列）

### 6.1 首次使用 → 第一次成功运行

```
启动 → 检测（无 provider 且无工作流）
  → 引导第1步（配置 provider，可跳过）
  → 引导第2步（选模板）
  → 引导第3步（填输入 → 运行）
  → 成功页（✓ + 打开编辑器）
```

### 6.2 调试一次失败

```
工作流列表 → 最近运行（失败）→ 运行详情
  → 失败节点自动展开（错误 + 建议）
  → [在编辑器中打开] → 画布选中该节点 + 属性面板定位到相关字段
  → 修改 → 运行 → 抽屉实时状态 → 成功
```

### 6.3 对比两次运行

```
运行列表 → 勾选 A/B → [对比]
  → 节点表（状态/耗时/token/Δ）
  → 展开输出 diff
  → [导出对比] 或 [以此配置重跑 B]
```

### 6.4 改坏后回退

```
编辑器 → 版本历史 → 选 v5 → 预览（只读）→ 恢复
  → 确认（当前保存为新版本）→ 画布回到 v5 → toast
```

## 9. 可访问性（v0.2 必须过）

1. 对比度：正文/标签 ≥ 4.5:1（`--ink-500` 已调到 `#6B706A`）；大字号 ≥ 3:1；状态色仅作辅助，必须同时有图标+文案。
2. 键盘：Tab 顺序 = 顶栏 → 页面工具栏 → 主内容 → 面板；画布节点可 Tab 聚焦（React Flow 默认支持），Enter 选中、Delete 删除。
3. 焦点：所有交互元素有可见焦点环；Modal/Drawer 焦点陷阱；Esc 关闭。
4. 语义：按钮用 `<button>`；图标按钮必须有 `aria-label`；运行状态区 `aria-live="polite"`（只播报状态变化，不播报每个 token）。
5. 动效：`prefers-reduced-motion` 下关闭流动边/呼吸点/过渡。
6. 缩放：浏览器 125%/150% 下不出现横向滚动（表格内部滚动除外）；窗口最小 1100×700。

## 12. 与工程实现的对接（可行性）

| 设计点 | 依赖的后端/契约改动 | 风险 |
|---|---|---|
| 节点输入可见 | `input_json` 写入 + `NodeRunDetail.input` 返回 | 低（字段已存在） |
| 失败分类与建议 | 前端映射 + 错误兜底（PRD B1/B2） | 低 |
| 运行对比 | `GET /api/runs/compare` + 行级 diff（前端实现） | 中（对齐规则要定） |
| 流式 | provider `stream()` + `node.delta` 事件 | 中（引擎事件扩充） |
| 模型列表 | `GET /api/providers/{id}/models` | 低 |
| 版本历史 | 新表 + 迁移 0003 + 3 个端点 | 中（恢复语义） |
