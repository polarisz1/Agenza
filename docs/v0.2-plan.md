## 7. 提交策略（按条目号）

每个任务完成后提交，提交信息格式：

```
feat(runs): 运行可观测 2.0 —— 节点输入、错误分类、运行对比（F1/B3）
fix(web): 列表列宽与固定操作列（B5）
```

一个提交可覆盖多个 ID（如 B1+B2 热修），但**不允许一个提交跨两个里程碑**。
文档与验收随对应任务提交；最后 `docs(v0.2): 更新 roadmap 与验收` 独立提交。

---

## 8. 验收命令（每个里程碑都跑）

```bash
pnpm check            # lint + ruff + format + typecheck + pytest + vitest + 契约漂移 + 兼容性
pnpm e2e              # 浏览器主链路 + 性能基线
uv run --directory apps/api alembic check    # 迁移无漂移（M5.4）
pnpm audit:js && pnpm audit:py               # 依赖无新增高危
```

新增能力必须同时补测试：后端 ≥ 1 条/任务，前端 store/纯函数 ≥ 1 条/任务，E2E ≥ 1 条/里程碑。
